# 스택챤(StackChan) 멀티기능 어시스턴트 설계 문서

**대상 하드웨어**: M5Stack Core2/CoreS3 (ESP32-S3) 본체 + ESP32-S3 N16R8 기반 e-paper 디스플레이 보드
**아키텍처**: 캐스케이드 (STT → LLM → TTS) + Function Calling 기반 의도 라우팅
**작성일**: 2026-08-25

---

## 1. 전체 구조

```
[마이크 입력]
   │  16kHz/16bit/Mono PCM (WebSocket 스트리밍)
   ▼
[Whisper API: STT] → 텍스트
   ▼
[GPT-4o mini: LLM + Function Calling]
   │
   ├─ 의도: 일반 대화        → 응답 텍스트 생성 → TTS
   ├─ 의도: 사진 찍기        → 카메라 캡처 함수 호출
   ├─ 의도: 공부 프로그램/음악 → SD카드 재생 함수 호출
   ├─ 의도: 인터넷 검색      → 검색 API 함수 호출 → 결과 요약 → TTS
   ├─ 의도: 타이머          → 타이머 시작 함수 호출
   ▼
[Google Cloud TTS] → 스피커 출력 (한/영 보이스 스위칭)
```

GPT-4o mini의 **Function Calling**으로 사용자 발화를 6개 기능 중 하나로 라우팅한다. 각 기능은 아래 정의된 tool 스키마에 대응한다.

---

## 2. 기능별 설계

### ① 일반 챗봇 (한국어/영어 대화)

- 기존 캐스케이드 파이프라인 그대로 사용 (Whisper → GPT-4o mini → Google TTS)
- 언어 감지 후 TTS 보이스를 `ko-KR` / `en-US`로 전환
- 별도 API 추가 불필요

### ② 사진 찍기 → 저장/출력/디스플레이 전송 / 인식

- 카메라 모듈로 촬영 → SD카드에 우선 저장
- 이후 사용자 선택에 따라:
  - **블루투스 열가압 프린터 출력**: ESC/POS 명령을 BLE Serial로 전송 (클라우드 API 아님, 펌웨어 내 프린터 드라이버 구현)
  - **e-paper 디스플레이 전송**: 별도 보드(GDEP073E01 7.3" 6색 E6 + ESP32-S3 N16R8)로 WiFi(HTTP POST) 또는 ESP-NOW를 통해 이미지 데이터 전송. 6색 e-paper 특성상 전송 전 **디더링/색상 양자화 처리** 필요
  - **사용자(얼굴) 인식**: ESP-WHO/ESP-DL 기반 온디바이스 얼굴 검출·인식. 가족 구성원 얼굴을 사전 등록해두고 로컬에서 판별. 인터넷 연결 불필요, 지연 없음, 사진이 기기 밖으로 나가지 않아 프라이버시 확보
  - **사물 인식(고양이/책/장난감 등)**: 촬영한 사진을 GPT-4o mini Vision(클라우드)에 전달해 임의 카테고리 객체를 자연어로 설명. 온디바이스 사전학습 모델(ESP-DL)은 사람 얼굴·고양이 얼굴(실험적)·보행자 정도만 지원하므로, 열린 카테고리 인식은 클라우드 비전으로 처리
- 저장/프린터/디스플레이 전송은 클라우드 API 불필요, 기기 간 통신 프로토콜 설계가 핵심 작업. 얼굴 인식은 온디바이스, 사물 인식은 클라우드로 역할을 분리함

#### ②-1. ESP-WHO 얼굴 등록 흐름 (가족 구성원 4명)

ESP-WHO/ESP-DL의 얼굴 인식은 얼굴 검출 → 특징 추출(feature vector) → SD카드 DB 저장/비교 구조이며, 등록은 이름이 아니라 순차 ID(정수) 단위로 이루어지므로 "ID ↔ 이름" 매핑을 앱 레벨에서 별도 관리한다.

**등록 단위**

| 항목 | 값 |
|---|---|
| 가족 구성원 수 | 4명 |
| 인당 등록 샘플 수 | 3장 (정면, 좌측 15°, 우측 15°) |
| 총 등록 feature 수 | 12개 |
| feature당 저장 용량 | 2,050 bytes (ID 2byte + feature 2048byte) |
| 총 저장 용량 | 약 24.6KB (SD카드) |

**등록 트리거 및 캡처 시퀀스**

```
사용자: "새로운 사람 등록해줘"
   ↓ GPT-4o mini Function Calling: enroll_face(name="")
   ↓ name 비어있으면 되묻기 → "이름이 뭐예요?" → 사용자 응답 → enroll_face(name="아빠") 재호출
[등록 모드 진입]
TTS: "카메라를 정면으로 봐주세요" → 캡처 → 얼굴 검출 실패 시 재시도 안내 → 성공 시 feature 추출 → DB 저장 (id=1)
TTS: "고개를 살짝 왼쪽으로 돌려주세요" → 캡처 → DB 저장 (id=2)
TTS: "이번엔 오른쪽으로 살짝 돌려주세요" → 캡처 → DB 저장 (id=3)
[id 1,2,3] → 매핑 테이블(SD카드 JSON)에 "아빠": [1,2,3] 기록
TTS: "아빠 등록 완료했어요!"
```

4명 반복 시 매핑 테이블 예시:
```json
{ "아빠": [1,2,3], "엄마": [4,5,6], "첫째": [7,8,9], "둘째": [10,11,12] }
```

**인식 흐름**

```
카메라 촬영 → 얼굴 검출 → feature 추출 → DB 매칭 → 최유사 id + 유사도(sim) 반환
   ↓ sim ≥ 임계값(예: 0.7)?
   예 → 매핑 테이블에서 id → 이름 조회 → GPT-4o mini에 "인식된 사람: OO" 컨텍스트 전달 → 응답 생성
   아니오 → "모르는 사람" 처리, 필요 시 신규 등록 유도
```

**삭제/재등록**

- "○○ 얼굴 삭제해줘" → `delete_face(name="○○")` → 매핑 테이블에서 해당 id 조회 → DB에서 feature 삭제 + 매핑 테이블에서 이름 항목 제거
- 재등록은 기존 항목 삭제 후 신규 등록 흐름 재실행

### ③ SD카드 공부 프로그램 / 음악 재생

- 스택챤용으로 자체 제작한 학습 콘텐츠(소마셈/팩토 등)를 SD카드에서 로드하여 로컬 재생
- 음악 재생도 SD카드 내 파일 재생 (I2S 오디오 출력)
- 런타임 클라우드 API 호출 없음

### ④ 인터넷 검색

- **Brave Search API** 또는 Google Custom Search JSON API 사용
- 아동용 기기 특성상 `safesearch=strict`(Brave) 또는 `safe=active`(Google) 옵션 필수 적용
- 검색 결과를 GPT-4o mini에 전달해 아이가 이해하기 쉬운 형태로 요약 후 TTS로 출력
- Bing Search API는 2025년 8월 완전 종료되어 선택지에서 제외됨

### ⑤ 타이머 (30분, 공부 프로그램 제외)

- 공부 프로그램 실행 시간과는 별도로 일반 사용(챗봇/음악 등)에 30분 타이머 적용
- 순수 펌웨어 로직 (카운트다운), 클라우드 API 불필요
- 타이머 종료 시 GPT-4o mini가 생성한 안내 멘트를 TTS로 출력 ("이제 그만해야 할 시간이야" 등)
- 공부 프로그램 사용 중에는 이 타이머 미적용

### ⑥ Hermes 연결 (추후)

- 현재 단계에서는 보류
- Hermes는 MQTT 기반 위성 프로토콜이므로, 추후 연결 시점에 별도 설계 문서로 다룰 예정

## 3. 필요 API 정리

| API | 용도 | 상태 |
|---|---|---|
| OpenAI Whisper API | STT | 확정 (기존 캐스케이드) |
| OpenAI GPT-4o mini API | LLM + Function Calling 라우팅 | 확정 (기존 캐스케이드) |
| Google Cloud TTS | TTS (한/영) | 확정 (기존 캐스케이드) |
| Brave Search API | 인터넷 검색 (④) | 확정 (`safesearch=strict`, `apikey.search`) |
| GPT-4o mini Vision (기존 GPT-4o mini API 재사용) | 사물 인식 (②-사물) | 별도 API 아님, 기존 LLM 호출에 이미지 입력만 추가 |

나머지 기능(②의 저장/프린터/디스플레이, ③⑤)은 클라우드 API가 아니라 펌웨어/하드웨어 통신 설계가 핵심이다. 얼굴 인식(②-얼굴)도 ESP-WHO/ESP-DL 온디바이스 처리로 클라우드 API 불필요.

## 4. 하드웨어 구성

| 구성 요소 | 사양 |
|---|---|
| 본체 | M5Stack Core2/CoreS3 (ESP32-S3) |
| 카메라 | 사진 촬영용 카메라 모듈 (모델 미정) |
| 프린터 | 블루투스 열가압 프린터 (ESC/POS, BLE Serial) |
| 외부 디스플레이 보드 | GDEP073E01 7.3인치 6색 e-paper (E6) + ESP32-S3 N16R8 |
| 저장 매체 | SD카드 (공부 프로그램 콘텐츠 + 음악 파일) |
