# 스택챤(StackChan) 음성 대화 파이프라인 설계 문서

**대상 하드웨어**: M5Stack Core2 / CoreS3 (ESP32-S3)
**작성일**: 2026-08-20
**결정**: 2026-08-26 — 기본 경로는 캐스케이드. Realtime 빌드는 선택 env로 유지.

---

## 1. 아키텍처 선택

두 가지 방식을 검토했으며, 본 프로젝트는 **캐스케이드(Cascade) 구조**를 기본으로 채택한다.

| 구분 | 캐스케이드 (STT → LLM → TTS) | Realtime API (OpenAI / Gemini) |
|---|---|---|
| 지연 시간 | 보통 10초 이상 | 거의 실시간 (수백 ms) |
| 월 비용 (월 900분 실사용 기준) | 약 $9~18 | 약 $18~135 |
| 구현 복잡도 | 상대적으로 단순 (각 API가 독립적) | ESP32단에서 오디오 스트리밍 프로토콜 구현 필요 |
| 빌드 | `m5stack-cores3` (기본) | `m5stack-cores3-realtime` (선택) |

→ **채택 이유**: 아동용 학습 콘텐츠는 응답 지연 10초 내외를 허용할 수 있는 용도이며, 비용 효율이 우선이다.

벤더 중간 서버(xiaozhi.me 등)와 warble식 PC 백엔드는 쓰지 않는다. 기기가 OpenAI·Google API를 직접 호출한다.

### 1-1. 선택된 구성 요소

| 역할 | 서비스 | 단가 |
|---|---|---|
| STT | OpenAI Whisper API (`language=ko`) | $0.006 / 분 |
| LLM | GPT-4o mini | $0.15 / 1M 입력 토큰, $0.60 / 1M 출력 토큰 |
| TTS | Google Cloud TTS | WaveNet $4/1M자 (기본) / Neural2 $16/1M자 (고음질 옵션) |

추정 비용: 약 $0.010/분(WaveNet) ~ $0.021/분(Neural2)

## 2. 오디오 포맷 규격

| 항목 | 값 | 근거 |
|---|---|---|
| 샘플링 레이트 | 16kHz | Whisper·주요 STT 엔진의 내부 처리 표준 해상도. 그 이상 녹음해도 인식률 개선 없이 대역폭만 낭비 |
| 비트 심도 | 16-bit | 음성 인식에 충분한 해상도 |
| 채널 | Mono (1채널) | 스테레오는 불필요한 데이터 중복 |
| 전송 형식 | Raw PCM (세션 시작 시 WAV 헤더 1회 전송, 이후 스트림은 헤더 없는 raw PCM) | 매 청크마다 WAV 헤더(44byte)를 반복 전송하는 오버헤드 제거 |
| 데이터 레이트 | 32KB/초 (256kbit/s) | 16,000Hz × 16bit × 1ch |

### 2-1. 메모리 배치 원칙

- I2S DMA 버퍼: **내부 SRAM**에 배치 (실시간성 확보, PSRAM 접근 지연 회피)
- 누적 오디오 버퍼(수백 ms ~ 수 초 분량): **PSRAM**에 `MALLOC_CAP_SPIRAM`으로 할당
- ESP32-S3 PSRAM(통상 8MB) 기준으로 위 데이터 레이트는 여유 있는 수준

## 3. 통신 프로토콜

### 3-1. WebSocket 상시 연결 채택

- HTTP 매 요청마다 TCP+TLS 핸드셰이크(수백ms~1초)가 반복되는 비효율을 제거하기 위해, **대화 세션 동안 WebSocket 연결을 유지**한다.
- 세션 종료 조건: 30초간 무응답 시 자동 종료 (스택챤_Ex 기본 동작과 일치) → 이때 WebSocket 연결도 명시적으로 close 처리하여 서버 리소스 낭비 방지.

### 3-2. 실전 체크리스트

- [ ] Keep-alive ping/pong 프레임 주기 설정 (라우터/NAT idle timeout, 보통 30~60초 대비)
- [ ] wss:// 사용 시 ESP32-S3 하드웨어 암호화 가속(AES/SHA) 활성화 여부 확인 → mbedTLS 부하 경감
- [ ] 재연결 로직: 네트워크 순단 시 WebSocket 재연결 및 세션 복구 처리
- [ ] 오디오 청크 전송 주기 결정 (예: 100~250ms 단위 청크로 스트리밍 전송, 서버측 STT가 스트리밍 지원 여부에 따라 조정)

---

## 4. 향후 결정 필요 항목

- STT를 실시간 스트리밍으로 받을지(청크 단위 부분 전송), 발화 종료 후 일괄 전송할지 방식 확정
- TTS 응답 음성 등급(WaveNet vs Neural2) — 아동 대상 콘텐츠 특성상 음질과 비용 트레이드오프 재검토
- 오프라인/로컬 처리(Module LLM) 병행 여부 — 네트워크 불안정 환경 대응. **warble PC 백엔드는 채택하지 않음.**
